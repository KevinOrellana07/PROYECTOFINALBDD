1. Descripción general y arquitectura

AutoAudit es un sistema de auditoría configurable para PostgreSQL. El administrador selecciona, a partir del diccionario de datos del DBMS, qué tablas y columnas deben monitorearse y qué eventos (INSERT, UPDATE, DELETE) registrar en cada columna. A partir de esa configuración el sistema genera automáticamente una función PL/pgSQL y un trigger AFTER ... FOR EACH ROW exclusivos para cada tabla, que registran cada modificación en una bitácora centralizada, normalizada e inmutable.

Flujo de funcionamiento

  1. El administrador consulta el diccionario (v_dic_tablas, v_dic_columnas) y elige tablas, columnas y eventos.
  2. La configuración se guarda en tabla_auditada, columna_auditada y configuracion_auditoria, validando existencia contra pg_catalog.
  3. fn_generar_trigger construye el código SQL con las columnas y eventos “compilados” y lo ejecuta.
  4. Cada INSERT/UPDATE/DELETE de los usuarios dispara el trigger, que escribe un encabezado (operación) y un detalle por columna afectada.
  5. Los auditores consultan el historial por usuario, por columna o por registro y exportan reportes.

Si la estructura de una tabla auditada cambia (RENAME, DROP COLUMN … CASCADE, DROP TABLE), dos event triggers sincronizan la configuración y regeneran el trigger automáticamente.

4. Manual de configuración y activación de auditoría por tabla

Solo los miembros del rol autoaudit_admin (usuario de ejemplo admin_auditoria) pueden configurar.

4.1 Desde la interfaz web

  1. Iniciar la aplicación (bash run.sh) y abrir http://localhost:8000. Ingresar como admin_auditoria.
  2. Menú Configuración: a la izquierda aparece el diccionario de datos con el estado de cada tabla.
  3. Seleccionar la tabla. Se muestran sus columnas (tipo, PK/FK, NOT NULL) con tres casillas: INSERT, UPDATE y DELETE. Al hacer clic en el encabezado de un evento se marcan/desmarcan todas las columnas.
  4. Escribir opcionalmente una descripción y pulsar Guardar y generar trigger. El sistema valida, genera el código, lo ejecuta y muestra la vista previa del SQL. Guardar sin aplicar solo guarda la configuración (estado PENDIENTE).
  5. Ver código SQL muestra la validación contra el diccionario y el código que se generará.
  6. Desactivar elimina el trigger conservando la configuración y la bitácora; Activar lo vuelve a generar. Regenerar reconstruye el trigger; Eliminar config. solo aparece si la tabla no tiene bitácora.

4.2 Desde SQL

-- Consultar el diccionario
SELECT * FROM auditoria.v_dic_tablas;
SELECT * FROM auditoria.v_dic_columnas WHERE esquema='tienda' AND tabla='productos';

-- Configuración granular (INSERT, UPDATE, DELETE) y generación
SELECT auditoria.fn_configurar_columna('tienda','productos','precio',     true,  true, true);
SELECT auditoria.fn_configurar_columna('tienda','productos','existencia', false, true, false);
SELECT auditoria.fn_generar_trigger(tabla_id) FROM auditoria.tabla_auditada
 WHERE esquema='tienda' AND tabla='productos' AND estado<>'HUERFANA';

-- Atajo: varias columnas con los mismos eventos y aplicar
SELECT auditoria.fn_configurar_tabla('tienda','clientes', ARRAY['nombre','email'], true, true, true);

-- Activar / desactivar / regenerar / estado
SELECT auditoria.fn_activar_tabla(1, false);
SELECT auditoria.fn_activar_tabla(1, true);
SELECT * FROM auditoria.fn_regenerar_todos();
SELECT * FROM auditoria.v_estado_auditoria;

4.4 Ejemplo de código generado

-- =====================================================================
-- Código generado automáticamente por AutoAudit. NO EDITAR A MANO.
-- Tabla origen : tienda.productos   (tabla_id = 2)
-- Generado     : 2026-11-02 16:44:56 por postgres
-- =====================================================================
CREATE OR REPLACE FUNCTION auditoria.fn_aud_2_tienda_productos()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, auditoria
AS $autoaudit$
DECLARE
    v_enc bigint;
BEGIN
    IF TG_OP = 'INSERT' THEN
        v_enc := auditoria.fn_crear_encabezado(2, 1::smallint, NULL, to_jsonb(NEW), jsonb_build_object('producto_id', NEW.producto_id));
        INSERT INTO auditoria.bitacora_detalle (encabezado_id, configuracion_id, columna_id, valor_anterior, valor_nuevo)
        VALUES (v_enc, 17, 6, NULL, NEW.nombre::text),
               (v_enc, 20, 7, NULL, NEW.precio::text);
        RETURN NULL;
    END IF;
    IF TG_OP = 'UPDATE' THEN
        IF OLD.nombre IS DISTINCT FROM NEW.nombre THEN
            v_enc := COALESCE(v_enc, auditoria.fn_crear_encabezado(2, 2::smallint, to_jsonb(OLD), to_jsonb(NEW), jsonb_build_object('producto_id', NEW.producto_id)));
            INSERT INTO auditoria.bitacora_detalle (encabezado_id, configuracion_id, columna_id, valor_anterior, valor_nuevo)
            VALUES (v_enc, 16, 6, OLD.nombre::text, NEW.nombre::text);
        END IF;
        IF OLD.precio IS DISTINCT FROM NEW.precio THEN
            v_enc := COALESCE(v_enc, auditoria.fn_crear_encabezado(2, 2::smallint, to_jsonb(OLD), to_jsonb(NEW), jsonb_build_object('producto_id', NEW.producto_id)));
            INSERT INTO auditoria.bitacora_detalle (encabezado_id, configuracion_id, columna_id, valor_anterior, valor_nuevo)
            VALUES (v_enc, 19, 7, OLD.precio::text, NEW.precio::text);
        END IF;
        IF OLD.existencia IS DISTINCT FROM NEW.existencia THEN
            v_enc := COALESCE(v_enc, auditoria.fn_crear_encabezado(2, 2::smallint, to_jsonb(OLD), to_jsonb(NEW), jsonb_build_object('producto_id', NEW.producto_id)));
            INSERT INTO auditoria.bitacora_detalle (encabezado_id, configuracion_id, columna_id, valor_anterior, valor_nuevo)
            VALUES (v_enc, 22, 8, OLD.existencia::text, NEW.existencia::text);
        END IF;
        RETURN NULL;
    END IF;
    IF TG_OP = 'DELETE' THEN
        v_enc := auditoria.fn_crear_encabezado(2, 3::smallint, to_jsonb(OLD), NULL, jsonb_build_object('producto_id', OLD.producto_id));
        INSERT INTO auditoria.bitacora_detalle (encabezado_id, configuracion_id, columna_id, valor_anterior, valor_nuevo)
        VALUES (v_enc, 18, 6, OLD.nombre::text, NULL),
               (v_enc, 21, 7, OLD.precio::text, NULL);
        RETURN NULL;
    END IF;
    RETURN NULL;
END;
$autoaudit$;

ALTER FUNCTION auditoria.fn_aud_2_tienda_productos() OWNER TO autoaudit_owner;
REVOKE ALL ON FUNCTION auditoria.fn_aud_2_tienda_productos() FROM PUBLIC;
COMMENT ON FUNCTION auditoria.fn_aud_2_tienda_productos() IS 'AutoAudit: trigger de auditoría de tienda.productos';

CREATE OR REPLACE TRIGGER trg_autoaudit
    AFTER INSERT OR UPDATE OF nombre, precio, existencia OR DELETE
    ON tienda.productos
    FOR EACH ROW
    EXECUTE FUNCTION auditoria.fn_aud_2_tienda_productos();

Características del código generado: una función por tabla (requisito: cada trigger maneja exclusivamente una tabla origen), columnas y eventos fijos en el código (sin consultar la configuración por fila), UPDATE OF columnas para no dispararse con columnas no auditadas, IS DISTINCT FROM para registrar solo cambios reales (incluyendo NULL), SECURITY DEFINER con dueño autoaudit_owner y search_path fijo.

5. Procedimiento de instalación y despliegue de triggers

5.1 Requisitos

  • Ubuntu 26.04 LTS con acceso sudo.
  • PostgreSQL 18 (lo instala el script si no existe).
  • Python 3 con venv (incluido en Ubuntu).

5.2 Instalación automática

cd autoaudit
sudo bash install.sh          # instala todo + datos de demostración
bash run.sh                   # inicia la aplicación en http://localhost:8000
sudo bash pruebas/ejecutar_pruebas.sh   # ejecuta las pruebas de validación

5.4 Despliegue de triggers en una tabla propia

  1. Crear la tabla en cualquier esquema (se recomienda que tenga llave primaria).
  2. Configurarla desde la interfaz o con fn_configurar_columna / fn_configurar_tabla.
  3. Generar con fn_generar_trigger. Verificar con SELECT * FROM auditoria.v_estado_auditoria (columna sincronizado = true) y en auditoria.v_dic_triggers.
  4. Los errores quedan en auditoria.log_generacion; si la generación falla, el trigger anterior permanece intacto.

Retencióndias_retencion y fn_purgar_bitacora() (solo superusuario).
